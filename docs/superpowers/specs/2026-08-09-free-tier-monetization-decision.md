# 無料ユーザー収益化 — AdSense 見送り後の比較判断記録

- 日付: 2026-08-09
- 状態: **次の実証へ進む**
- 種別: 判断記録。実装指示ではない
- 前提: [Google AdSense 導入 — 見送りの判断記録](./2026-08-09-adsense-decision.md)

---

## 結論

無料ユーザーを含む事業の**主収益は Plus** とする。次点として、買い物の文脈に限定した
Amazon または楽天の**成果報酬テキストリンクを小規模に実証**する。任意の単発支援は、
利用継続を支える補助的な選択肢にとどめる。

現時点では、次を採用しない。

- 広告配信スクリプトの導入
- スポンサーによる献立内容への介入
- 広告収益を目的とする公開 SEO 面の新設

Plus は既存製品との整合性が最も高く、第三者広告スクリプトを必要としない。成果報酬
リンクは買い物という既存の利用目的に近いが、規約、表示、プライバシーおよび実収益を
小さく検証する必要がある。単発支援は購入価値の提供ではなく善意に依存するため、主収益
としては扱わない。

本書が決めるのは**実装開始ではなく、次に何を計測して判断するか**である。以下では、
確認済みの事実を「事実」、まだ根拠がない見通しを「推測」、人間または規約確認が必要な
事項を「要確認」と明記する。

## 1. 現状

### 1.1 確認済みの製品条件（事実）

- Free の献立生成成功上限は **1 日 3 回**、Plus は **1 日 10 回**。
- Plus は生成品質の向上とチラシ活用を価値として提示している。
- Plus 価格は **月額 580 円（税込）**、**年額 5,800 円（税込）**、**7 日間の試用**あり。
- `PLUS_LP_UPGRADE_COMING_SOON=true` により、現在は UI と API の双方で申込を停止して
  いる。
- 商用判断に使える analytics は未導入。
- OpenRouter 利用料が主な変動費である。

### 1.2 現状からの含意

- **推測**: Plus は既存の上限差・品質差から価値仮説を説明しやすい。一方、申込停止中で
  商用 analytics もないため、現時点で転換率や継続率を事実として述べることはできない。
- **要確認**: Free と Plus の実測 AI 原価、試用から有料への移行、返金・異議申立て、
  解約後の収支を計測しなければ、Plus の採算は確定しない。

## 3. 2026-08-09 時点の公式条件

以下は各公式ページを 2026-08-09 時点の判断材料として整理したもの。料率・条件は変更
され得るため、実装直前と公開後の定期確認が必要である。

### 3.1 Amazon アソシエイト（事実）

- 食品・飲料の紹介料率は **8%**、キッチン用品は **3%**。
- 所定のアソシエイトである旨の必須文言、申込み後の審査、運営規約の遵守が必要。
- 紹介料率、対象カテゴリおよび審査条件は変動し得る。

出典: [Amazon アソシエイト・プログラム紹介料率表](https://affiliate.amazon.co.jp/help/node/topic/GRXPHT8U84RAYDXZ)、
[Amazon アソシエイト・プログラム運営規約](https://affiliate.amazon.co.jp/help/operating/agreement/)

### 3.2 楽天アフィリエイト（事実）

- 食品の料率は **4%**、キッチン用品は **3%**。
- クリック後 **24 時間以内に買い物かごへ追加**され、**89 日以内に購入**された成果が
  対象となる条件がある。
- 通常の成果報酬上限は **1 商品 1,000 円**、同一ユーザーによる購入は **月 3,000 円**。
- 料率、成果条件、上限および対象カテゴリは変動し得る。

出典: [楽天アフィリエイト ガイドライン・規約](https://affiliate.rakuten.co.jp/guideline/rule/)

### 3.3 Stripe（事実）

- Payment Links の作成・利用自体は **無料**。
- 国内カード決済手数料は **3.6%**。
- 継続課金に Stripe Billing を使う場合は **0.7%**。
- 実際の費用は決済手段、契約、返金、異議申立て等で変わり得る。

出典: [Stripe 日本の料金体系](https://stripe.com/jp/pricing)、
[Stripe Payment Links](https://stripe.com/jp/payments/payment-links)

### 3.4 広告であることの表示（事実）

広告であるにもかかわらず一般消費者が広告と判別しにくい表示は、景品表示法上の
ステルスマーケティング規制の対象となる。成果報酬リンクやスポンサー表示は、広告・収益
関係が分かる表示をリンクまたは内容の近傍に置く。

出典: [消費者庁「ステルスマーケティングに関する景品表示法上の考え方」](https://www.caa.go.jp/policies/policy/representation/fair_labeling/stealth_marketing/)

### 3.5 認証必須面の参加資格（要確認・blocker）

成果報酬リンクの候補面 `/shopping` は認証必須である。Amazon、楽天とも、登録媒体、
公開性、独自コンテンツ、審査時の閲覧可能性などの参加・審査条件を定めており、公式条件は
変動し得る。認証必須面を媒体として登録できるか、審査者が適法・安全に確認できるか、
現在の独自コンテンツが要件を満たすかを、選定 ASP の最新公式資料と照合する。

これは Phase 2 の明示的な blocker である。いずれかを確認できない、または条件を満たさない
場合、その ASP は見送る。公開 SEO 面を新設して条件を回避することは、本判断の範囲外で
あり現時点では行わない。

実装前の確認先: [Amazon アソシエイト審査要件](https://affiliate.amazon.co.jp/help/node/topic/G8TW5AE9XL2VX9VM/)、
[Amazon プログラムポリシー](https://affiliate.amazon.co.jp/help/operating/policies/)、

## 4. Plus の簡易採算式

判断に使う概念式は次のとおり。

> Plus 売上寄与 = 会員数 × 価格 − 決済・Billing 手数料 − AI 原価 − 返金等

ここで「価格」は手数料控除後の受取額ではなく、表示価格の gross を指す。実証でこの式を
使うときは、月額と年額を分け、同じ売上認識期間へ按分し、税込／税抜を統一する。また、
Free 基準原価ではなく Plus 増分 AI 原価を一度だけ控除する。詳細な定義は Phase 0A で固定
する。

国内カード **3.6%** と Billing **0.7%** を価格に単純適用した参考値は次のとおり。

- 月額 580 円: `580 × (1 − 0.036 − 0.007) ≒ 555 円`
- 年額 5,800 円: `5,800 × (1 − 0.036 − 0.007) ≒ 5,551 円`

これは**採算や入金額の確定値ではない**。税の会計上の扱い、返金、異議申立て、固定の
追加費用、決済手段差、試用、実際の AI 原価その他の実コストを除外した参考計算である。
これらを織り込まずに価格や利益を決めてはならない。

成果報酬は、購入時点の表示金額をそのまま計算基礎にしない。Amazon は**ASP が確定した
適格収入 × 適用料率**を基礎とし、不適格注文、返品、返金等を除外する。楽天は商品・
同一ユーザーの上限、否認、取消等を反映した**ASP の確定成果報酬**を正本とする。いずれも
ASP の確定値を超える収益予測は行わない。

## 5. 成果報酬リンク実証の不変条件

Phase 2 に進む場合も、次は設計上の不変条件とする。

1. 買い物リスト全体を外部へ自動送信しない。
2. 手入力または編集済みの文字列は、検査や明示確認の有無にかかわらず、動的外部送信の
   対象へ昇格させない。
3. 買い物項目由来で外部へ渡せる動的検索語は、サーバー管理の承認済み固定語彙 ID から
   導出する不変の単一検索語だけとする。未知の ID、語彙との不一致、長さ・制御文字等の
   完全性検証への不合格は fail-closed で拒否する。未知の自由文を機微語検出によって許可
   する代替経路は設けない。
4. 外部送信の直前に、実際に送る文字列と遷移先 ASP をユーザーへ表示し、明示確認後の
   クリックでのみ送信する。
5. 固定リンク方式を使う場合も、選定 ASP が公式に許可したリンクだけに限定する。
6. 遷移先は固定した HTTPS の origin と path の allowlist に限定し、検索語は標準的な
   query encoding を用いて安全に組み立てる。ASP 公式方式が許可しない URL 改変、任意の
   redirect、ユーザー入力 URL への遷移を許可しない。
7. 外部遷移であること、および広告・収益リンクであることをリンクの近傍に表示する。
8. 検索語と完全な遷移 URL を、アプリケーションログや analytics のイベントに保存しない。
9. 第三者 JavaScript や計測ピクセルを組み込まない。
10. 商品価格・商品画像・商品 API の利用は本実証に含めず、採用前に各社規約を別途確認
   する。
11. プライバシー文言と、法令・送信内容・利用サービスに照らして必要となる同意を、実装前
    に確定する。

## 6. 段階的な実証と判断ゲート

数値目標は現時点で発明しない。以下の各 KPI の採用可否と閾値は、計測設計と人間判断を
経て「要決定」とする。

### 6.1 データとイベントの共通原則

- 契約、試用、請求、返金等に必要な **billing operational data** と、判断用の
  **analytics 出力**を分離する。運用上必要な識別可能データまで「使わない」とはしないが、
  analytics に識別可能な個票を残さない。
- 同一 cohort の転換・継続を算出するための cohort key、event time、成熟条件、観測期間、
  削除要求時の扱い、集計後の個票破棄、アクセス権限、保持期間は、次 Task
  「プライバシーを守る収益計測設計」で確定する。
- checkout 開始、paid、返金・chargeback、AI 原価、quota 到達はサーバーまたは Stripe の
  正本から取得し、成果報酬の確定成果は ASP の正本を使う。
- LP 表示、CTA 表示・選択、リンク表示・選択等の client event は参考指標とする。idempotency、
  重複排除、bot、内部利用、テスト traffic の除外を設計し、client の申告だけで売上、原価、
  quota、確定成果を決めない。
- すべての率は、分子と分母を同一の eligibility、surface、cohort、観測期間に限定する。
  イベント間の帰属条件と重複排除単位も Phase 0A で先に固定し、異なる母集団を同じ率に
  混在させない。

### Phase 0 — 集計設計、計測実装、観測

#### Phase 0A — 集計設計（次 Task、実装しない）

- **入口条件（事実）**: 商用 analytics がなく、申込が UI / API で停止している現状から
  開始する。
- **実証内容**: analytics に識別可能な個票を残さず、CTA 表示数、CTA 選択数、Plus LP
  表示数、checkout 開始数、Free 上限到達数を集計できる設計と、AI 原価の集計設計を作る。
  実装はまだ行わない。
- **先に固定する定義（要決定）**:
  - KPI ごとの eligibility、surface、観測期間、event time、cohort key、成熟条件、イベント
    間の帰属条件
  - Free 上限到達を重複排除する単位（利用者、JST 日、到達機会等）
  - 月額と年額を比較可能にする期間按分と売上認識期間
  - 税込／税抜、gross（控除前売上）、決済後 net、返金・chargeback の用語と計上時点
  - Free の基準 AI 原価と Plus による増分 AI 原価。生成失敗、repair、品質向上、チラシ
    利用をどちらへ配賦するか
  - 共通費と一時費の配賦規則、および各費用を全体で一度だけ計上する規則
  - billing operational data と analytics 出力の境界、集計後の個票破棄、削除、権限、保持
- **KPI 式（要決定）**:
  - `CTA 選択率 = 同一 eligibility・surface・cohort・観測期間の重複除外済み CTA 選択数 ÷ 同じ母集団の重複除外済み CTA 表示数`
  - 導線上必要なら `CTA 後 LP 到達率 = 同一 cohort・観測期間で CTA に帰属する適格 Plus LP 表示数 ÷ 同じ母集団の重複除外済み CTA 選択数`
  - 限定 pilot では `checkout 開始率 = 同じ pilot cohort のサーバー正本 checkout 開始数 ÷ 同 cohort で checkout 対象だった重複除外済み適格 Plus LP 表示数`
  - `上限到達後 LP 到達率 = 同一 cohort・観測期間で上限到達イベントに帰属する適格 Plus LP 表示数 ÷ Phase 0A 所定単位で重複除外したサーバー正本の Free 上限到達数`
  - `Free 基準 AI 原価／成功 = Free に配賦した AI 原価 ÷ Free の生成成功数`
  - `Plus 増分 AI 原価／成功 = Plus にのみ追加配賦した AI 原価 ÷ Plus の生成成功数`
- **停止条件**: cohort を扱う billing operational data と analytics 出力を安全に分離
  できない、プライバシー文言・保存期間・集計境界・原価配賦を確定できない、または売上・
  AI 原価を信頼できる正本から集計できない場合は設計を承認しない。具体的な KPI 閾値は
  **要決定**。Phase 0A の承認だけで計測実装へ自動的に進んではならない。

#### Phase 0B — 計測実装・検証・観測（人間承認後の別 Task）

- **入口条件**: 人間が Phase 0A の設計を承認し、計測実装を行う別 Task の範囲と検証条件を
  明示していること。
- **実証内容**: 承認済み設計どおりに計測を実装・検証し、申込停止中に取得可能な CTA
  表示、CTA 選択、LP 表示、上限到達、AI 原価を所定の観測期間だけ収集する。checkout
  開始率の本番観測は、申込を限定解放する Phase 1B で行う。
- **完了条件**: Phase 1A に使う集計が所定の観測期間を満たし、Phase 0A で定めた成熟条件と
  代表性の条件を満たすこと。欠測、重複、bot、内部利用、テスト traffic の影響を評価し、
  設計どおり除外または明示できること。
- **停止条件**: 実装が承認済みのデータ境界を越える、検証に失敗する、または成熟性・代表性
  を満たす集計を得られない場合は Phase 1A に進まない。

### Phase 1 — Plus の限定 pilot と一般解放判断

- **入口条件**: Phase 0B が完了し、成熟性・代表性の条件を満たす集計があること。加えて、
  プライバシー文言、保存期間、AI 原価の算定方法、販売主体・税務・返金運用、KPI 閾値が
  確定していること。

#### Phase 1A — 限定解放前ゲート

- **判断**: 申込停止中でも取得できる LP、CTA、上限到達の需要シグナルと、価格・手数料・
  許容増分 AI 原価による事前採算を評価する。この時点では、限定解放後にしか得られない
  checkout 開始率、転換率、継続率を合格条件にしない。
- **KPI 式（要決定）**:
  - Phase 0A で定義した CTA 選択率、上限到達後 LP 到達率
  - `事前単位寄与 = 期間按分した税込または税抜 gross − 決済・Billing 手数料 − 想定返金等 − Plus 増分 AI 原価 − 配賦費用`
- **停止条件**: 法務・運用・計測が未確定、または事前単位寄与と需要シグナルが人間の
  定める閾値を満たさない場合、申込停止を維持する。

#### Phase 1B — 限定 pilot

- **判断**: `PLUS_LP_UPGRADE_COMING_SOON` による UI / API の停止を、事前に定めた限定
  対象だけに整合して解放し、試用、有料転換、継続、原価、返金・chargeback を観測する。
- **要決定**: 限定対象、開始・終了条件、判定期間、cohort の成熟条件、利用者への説明、
  UI と API を同時に再閉鎖する即時条件。
- **KPI 式（要決定）**:
  - Phase 0A で定義した checkout 開始率（同じ pilot cohort の分子・分母だけを使う）
  - `有料転換率 = 成熟した試用開始 cohort のうち有料開始した件数 ÷ 同 cohort の試用開始数`
  - `継続率 = 必要な観測期間を満たした有料開始 cohort のうち継続条件を満たす件数 ÷ 同 cohort の有料開始数`
  - `Plus 単位寄与 = 同一認識期間の gross − 決済・Billing 手数料 − 返金・chargeback − Plus 増分 AI 原価 − 配賦費用`
- **即時再閉鎖条件**: 課金・entitlement の不整合、誤請求、削除・プライバシー境界の破綻、
  原価の異常、または人間が定める安全・採算条件への抵触。具体的な条件は pilot 前に
  **要決定**。

#### Phase 1C — 一般解放／継続ゲート

- **判断**: 成熟した pilot cohort の転換、継続、返金・chargeback、Plus 単位寄与、運用
  負荷を基に、一般解放、pilot 継続、再閉鎖のいずれかを決める。
- **停止条件**: 成熟 cohort が不足している間は一般化しない。人間が定める転換・継続・
  採算・安全の閾値を満たさない場合は一般解放せず、必要に応じて再閉鎖する。閾値と観測
  期間は**要決定**。

### Phase 2 — 成果報酬テキストリンク限定実験

- **入口条件**: Phase 1 の Plus 判断が完了し、採用 ASP、対象リンク、必須表示、
  プライバシー文言、必要な同意、不変条件、KPI 閾値が確定していること。さらに選定 ASP の
  最新公式資料から、次を確認する。
  - 公式に許可されたリンク生成方法、URL 形式、改変可能範囲
  - 認証必須の `/shopping` の媒体登録可否、審査時の閲覧可能性、公開性・独自コンテンツ等
    の参加資格
  - 成果確定までの期間、否認・取消・返品・上限の反映方法
- **blocker**: 上記を確認できない、または満たせない ASP は採用しない。動的検索リンクが
  許可されない場合は、ASP が公式に発行・許可した固定リンクだけに限定する。それも成立
  しなければ Phase 2 自体を見送る。
- **実証内容**: 買い物文脈の一部に、本書の検証と明示確認を通った単一検索語のテキスト
  リンク、または許可済み固定リンクだけを小規模に置く。第三者 JS、ピクセル、商品価格・
  画像 API は使わない。
- **KPI 式（要決定）**:
  - `リンク選択率（参考） = 重複等を除いた成果報酬リンク選択数 ÷ 重複等を除いたリンク表示数`
  - `クリック当たり確定成果件数 = 成熟したクリック cohort に帰属する ASP 確定成果件数 ÷ 同 cohort の適格クリック数`
  - `クリック当たり確定成果報酬 = 成熟したクリック cohort の ASP 確定成果報酬 ÷ 同 cohort の適格クリック数`
  - `実証純寄与 = ASP 確定成果報酬 − Phase 2 に一度だけ配賦した実装・運用・問い合わせ対応コスト`
- **停止条件**: 不変条件を満たせない、広告表示や規約遵守を担保できない、誤送信・意図しない
  データ送信が見つかる、媒体資格・リンク方式が不適格となる、ユーザー体験を損なう、
  または人間が定める成熟成果・純寄与の閾値を満たさない場合は直ちに停止する。各閾値と
  成熟期間は**要決定**。

### Phase 3 — 継続または撤退

- **入口条件**: Phase 1 と、実施した場合は Phase 2 について、定めた判定期間の集計が完了
  し、規約・プライバシー・問い合わせを含む運用負荷を評価できること。
- **実証内容**: Plus、成果報酬リンク、任意単発支援の順に、継続・修正・撤退を判断する。
  単発支援はこの段階でも主収益へ自動昇格させない。
- **KPI 式（要決定）**:
  - `チャネル純寄与 = 同一認識期間のチャネル gross または ASP 確定成果報酬 − 当該チャネルに一度だけ配賦した控除・増分原価・返金等・運用コスト`
  - `全体純寄与 = Plus 純寄与 + 成果報酬純寄与 + 単発支援純寄与`
- **配賦原則**: Free 基準 AI 原価、Plus 増分 AI 原価、共通費、一時費を Phase 0A の規則で
  一度だけ計上し、チャネル合算時に AI 原価その他の費用を二重控除しない。
- **停止条件**: 純寄与が人間の定める閾値を満たさない、規約変更やプライバシーリスクへ
  継続対応できない、または献立支援という製品目的より収益導線が優先される場合は、その
  チャネルから撤退する。閾値と判定期間は**要決定**。

## 7. 次の Task と人間が決める事項

次の Task は **「プライバシーを守る収益計測設計」** とする。Phase 0A の集計境界、イベント
定義、保存期間、閲覧権限、削除、プライバシー文言、同意要否を設計する Task であり、
**収益化機能の実装はまだ行わない**。

### 7.1 全チャネル共通の前提

人間は、analytics と運用データの境界、KPI の定義・閾値・判定期間、プライバシー文言、
必要な同意、原価・共通費・一時費の配賦を決める。当該 Phase に必要な共通前提が未決定
なら、その Phase に進まない。

### 7.2 チャネル別の前提

- **Plus（Phase 1）**: 販売主体と税務上の取扱い、許容する AI 原価と最低採算、限定対象、
  pilot の判定期間、即時再閉鎖条件を決める。
- **成果報酬（Phase 2）**: ASP（Amazon、楽天、または見送り）、登録媒体適格性、リンク
  生成方式、リンク対象と表示位置を決める。
- **任意単発支援**: 実証に進む場合だけ、返礼、返金方針、販売・寄付・税務上の取扱いを
  決める。

後続の ASP や単発支援の判断が未決定であることだけを理由に、Plus の Phase 1 を止めない。
一方、各チャネル固有の前提が未決定なら、そのチャネルの実装には進まない。スポンサーに
よる献立介入と広告目的の公開 SEO 面は、引き続き現時点不採用とする。
